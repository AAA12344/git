> 本文给项目成员阅读。AI 的强制规则见根目录 `AGENTS.md` 和 `src/modules/AGENTS.md`。

## 分工原则

每个模块可以由一名或多名维护人共同负责。每位成员在单个任务中默认只处理一个一级模块目录；一个任务、一个分支、一个 PR，不同时修改无关模块。确实需要共享能力时，先单独提交“共享基础能力 PR”，合并后各模块再继续开发。

## 推荐的近期人员分配

如果现在加入更多成员，建议优先分配以下互不冲突的工作：

1. 成员 A：`consumer-review/`，完善消保审查。
2. 成员 B：`education/`，完善宣传教育。
3. 成员 C：`notifications/`，完善通知中心后续能力。
4. 成员 D：`admin/organizations/`、`admin/config/`、`admin/form-config/`、`admin/users/`、`admin/permissions/` 或 `admin/operations/`，一次只选一个子模块。
5. 负责人/架构维护者：继续把 `app.js` 中的投诉管理逐组迁出，并拆分统计源码。

不要让两个人同时修改 `app.js` 的不同区域。即使 Git 能自动合并，页面状态、动作名称和共享数据也可能发生语义冲突。

## 剩余结构迁移量

后台管理已经全部迁出 `app.js`。剩余结构迁移预计为 5～10 个聚焦 PR：

1. 溯源整改分阶段字段控件、统计筛选状态、持久化与流转：1 个 PR。
2. 子流程创建、处理和详情：1～2 个 PR。
3. 审批工作台与分类审批：1 个 PR。
4. 工单创建、处理、详情、查询和导出：2～3 个 PR。
5. 统计分析、首页和报告中心源码拆分：2～4 个 PR。
6. `app.js` 最终共享代码收口：1 个 PR.

真实后端接口边界不计入上述数量。它应在页面边界稳定后，以 repository、schema 和 contract test 为单位另行规划。新手成员现在优先接手上表中“是”或已迁移的目录；仍在 `app.js` 或 `statistics-module.source.jsx` 的工作由架构维护者先拆边界。交接操作见 [新手交接清单](新手交接清单.md)。

## 维护人配置

维护人确定后，修改 `.github/CODEOWNERS`，在对应路径后列出一名或多名 GitHub 用户或组织团队。例如：

```text
/src/modules/education/ @education-owner @education-reviewer
/src/modules/notifications/ @notice-owner @notice-reviewer
```

同一条路径的共同维护人必须写在同一行。如果一级模块与子模块由不同人员负责，把更具体的子模块规则写在宽泛规则后面；GitHub 对同一文件只采用最后一个匹配规则，不会把多行维护人自动合并。

CODEOWNERS 负责自动邀请维护人审查，但同一路径列出多人时，GitHub 的“Require review from Code Owners”只需要其中任意一名 Code Owner 批准。需要两人或更多人批准时，还要在 `main` 的 Branch protection 或 Ruleset 中设置 Required number of approvals。组织仓库还可以通过 Ruleset 的 Required reviewers 按路径要求指定团队及团队内批准人数。

所有个人或团队 Code Owner 都必须具有仓库写权限；组织团队还必须可见并具有明确写权限。配置说明见 [GitHub CODEOWNERS 文档](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/about-code-owners) 和 [分支保护文档](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-protected-branches/about-protected-branches)。

## 跨模块需求处理

例如宣传教育和通知中心都需要“附件上传”：

1. 先由提出者写清两个模块共同需要的接口。
2. 在 `src/shared/` 或 `src/core/` 中做一个小型共享能力 PR。
3. 共享 PR 通过测试并合并。
4. 两个模块分别在自己的分支接入。

不要直接从一个模块复制代码到另一个模块，也不要让模块直接读取另一个模块的 DOM 或内部状态。
